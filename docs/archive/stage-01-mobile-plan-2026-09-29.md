## 1. Почему версия 3.0

Версия 2.0 описывала контракт 1.0.0 — тот, что backend действительно реализовал
в сентябре. 22 сентября в `terentiy_ai` пришёл контракт 1.1.0-draft, и мобильное
API изменилось целиком.

| Контракт 1.0.0 (реализован) | Контракт 1.1.0-draft (описан) |
|---|---|
| `mobile/activate` + PIN из шести цифр | `auth/register`: код установки, логин, пароль от 12 символов |
| `mobile/login` по `device_id` и PIN | `auth/login` по логину и паролю |
| Токен opaque, бессрочный, не отзывается | access 15 минут + refresh с ротацией, `auth/logout`, `password-reset/*` |
| `GET /agents` — только технические флаги | `GET /home` — состояние наблюдения, счётчик непросмотренных, интервал опроса |
| Наблюдением управлять нельзя | `PUT /agents/{id}/observation` с промежуточными состояниями |
| Журнала событий нет | `GET /events`, `GET /events/{id}` — `possible_fall` с курсорной пагинацией |
| `latest-image` — два base64-JPEG в JSON | `GET /media/{id}` — кадр и 30-секундный клип двоичным телом |
| `Boolean?` для флагов | `camera: connected \| unavailable \| unknown` |

Вместе с контрактом пришли ТЗ `android-demo-mobile-tz.md` и сториборд из пяти
экранов с проработанным визуалом — он и стал основой дизайн-системы.

## 3. Два источника данных

Реализации репозиториев две, интерфейс один:

- **Сетевая** — по контракту 1.1.0, готова к появлению backend;
- **Демо** — сценарий внутри приложения: подключение и вход принимают любые
  корректные данные, наблюдение проходит `starting` → `enabled` за две секунды,
  через 20 секунд появляется событие `possible_fall`, в истории лежат ещё два
  события разной давности.

Переключатель — в Профиле; выбор читается при каждом вызове, поэтому
переключение действует сразу и без пересборки. По умолчанию включено демо:
пока backend не отдаёт контракт, сетевой режим показать нечего.

**Кадр в демо настоящий** — снимок с камеры установки из `var/ml-diagnostics`
репозитория `terentiy_ai`, лежит в `res/raw/demo_fall_frame.jpg`.
**Клипа нет ни в демо, ни на сервере**, поэтому демо честно проводит его через
`preparing` → `unavailable` с причиной, а не изображает видео, которого не существует.
Проигрыватель (Media3) не добавлен: проверять его не на чем.

## 4. Принятые решения

### 4.1. Обновление сессии сериализуется

Контракт требует ротации refresh-токена, и повторное предъявление уже
потраченного токена **отзывает всю token family устройства**. Наивная
реализация ломается именно тогда, когда всё работает нормально: два
одновременных запроса получают `401`, оба берут один refresh-токен, первый
успевает, второй сжигает сессию. `TokenAuthenticator` сериализует обновление
`Mutex` и внутри критической секции проверяет, не обновил ли сессию кто-то
другой. См. [ADR-0005](../adr/0005-serializatsiya-obnovleniya-sessii.md).

### 4.2. Сессия хранится одной записью

Access и refresh лежат в шифрованном хранилище **вместе**, одной строкой:
раздельные ключи допускают состояние, в котором один токен обновился, а второй нет.

### 4.3. Material You отключён

`dynamicColor = false`. Иначе Material You перекрашивает фирменный зелёный под
обои устройства, и от дизайн-системы остаётся один силуэт.

### 4.4. Промежуточные состояния показываются честно

Команда наблюдения доставляется агенту асинхронно: сервер отвечает `202` и
состоянием `starting` или `stopping`, а подтверждение приходит следующим
heartbeat. На это время кнопка блокируется и показывает индикатор — иначе
пользователь отправит противоположную команду поверх неподтверждённой.

### 4.5. Частоту опроса задаёт сервер

Интервал берётся из `poll_after_seconds` ответа `GET /home`, а не из константы
приложения: только сервер знает, как часто обновляются данные на его стороне.
Значение ограничивается диапазоном 1–300 секунд — нулевой интервал превратил бы
опрос в цикл без пауз.

### 4.6. Формулировки не усиливаются

`statement` приходит с сервера и намеренно нейтрален: система сообщает, что
эпизод требует проверки, и не утверждает, что человек упал. Приложение этот
текст не переписывает.

### 4.7. Остаётся в силе с предыдущей версии

`device_id` — UUIDv4, сгенерированный приложением ([ADR-0004](../adr/0004-proiskhozhdenie-device-id.md));
адрес сервера вводится в приложении и подменяется интерцептором; имя
пользователя хранится локально.

## 5. Технологический стек

| Область | Выбор | Роль |
|---|---|---|
| Язык | Kotlin 2.2.10 | Корутины и Flow для опроса |
| minSdk / targetSdk | 26 / 37 | Как в репозитории |
| UI | Jetpack Compose + Material 3 | Экранов мало, состояний много |
| Архитектура | MVVM, поток UiState → ViewModel → Repository | Экран отделён от источника данных |
| DI | Hilt 2.59.2 | Версия выбрана под AGP 9: в 2.57–2.58 используется удалённый `BaseExtension` |
| Сеть | Retrofit + OkHttp + kotlinx.serialization | Интерцепторы адреса и токена, `Authenticator` для обновления |
| Секреты | AndroidKeyStore + SharedPreferences | `device_id` и сессия, AES/GCM |
| Настройки | DataStore Preferences | Имя, `household_id`, адрес сервера, режим источника |
| Навигация | Navigation Compose | Семь маршрутов, таб-бар внутри вкладок |
| Иконки | Собственные `ImageVector` | `material-icons-extended` устарела и тянет лишнее |
| Кадр | `BitmapFactory` | Одна картинка на экран — Coil здесь нечего обслуживать |
| Тесты | JUnit, MockWebServer, Turbine, Compose UI Test | Контракт проверять живым сервером нечем |
| Диагностика | Timber | Технические коды пользователю не показываются |

**Не добавлено осознанно:** Room и Paging 3 (история короткая, кэш пережил бы
ровно один экран), Coil (одна картинка), Media3 (клипа не существует).
Условия возврата — в [`docs/backlog-mobile.md`](../backlog-mobile.md).

## 8. Проверка результата

```bash
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleDebug
./gradlew :app:lintDebug
```

**Unit-тесты:** разбор перечислений контракта и неизвестных значений; мапперы
DTO → domain, включая защиты от нулевого интервала опроса и неразбираемого
времени; `ErrorMapper` на обоих форматах ошибок backend и на теле, которое не
является ни тем, ни другим; **`TokenAuthenticator` под двумя параллельными
`401` — обновление должно произойти ровно один раз**.

**MockWebServer:** каждый маршрут контракта 1.1.0 — `register`, `login`,
`refresh`, `logout`, `home`, `observation` с `202`, курсорная пагинация
`events`, `events/{id}`, двоичный ответ `media/{id}`.

**Compose UI:** экраны подключения, входа, главная во всех состояниях
наблюдения, история, карточка события по состояниям клипа, профиль с выходом.

**Ручной прогон в демо-режиме,** без запущенного backend:

| Шаг | Ожидаемо |
|---|---|
| Подключение с любым кодом от 8 символов и паролем от 12 | Успех, открывается главная |
| Пароль короче 12 символов | Кнопка неактивна, запрос не уходит |
| Логин кириллицей | Кнопка неактивна |
| Главная сразу после подключения | «Наблюдение выключено», камера подключена |
| Нажать «Включить наблюдение» | Индикатор на кнопке, через две секунды «Наблюдение включено» |
| Подождать 20 секунд | Коралловый баннер тревоги, счётчик непросмотренных |
| «Открыть событие» | Карточка с настоящим кадром и нейтральной формулировкой |
| Состояние клипа | «Готовится», затем «недоступно» с причиной — не пустой плеер |
| Вкладка «История» | Три события, открытое отмечено просмотренным |
| Профиль → «Выйти из аккаунта» | Подтверждение, затем экран входа |
| Повторный вход | Главная, состояние наблюдения сохранилось |
| Перезапуск приложения | Главная без повторного входа: сессия переживает перезапуск |

**Светлая и тёмная тема** — переключением системной настройки эмулятора.

**Сетевой режим** проверяется в день появления backend: переключатель в Профиле,
пересборка не нужна.

## 9. Риски

| Риск | Смягчение |
|---|---|
| Контракт помечен `draft` и изменится снова | Владелец — `terentiy_ai`, здесь копия с номером коммита; DTO изолированы от доменных моделей, правка ограничивается мапперами |
| Backend реализует контракт иначе, чем описано | Демо-режим позволяет показывать приложение, не дожидаясь; сетевые тесты написаны по схеме и поймают расхождение в первый же день |
| Ротация refresh-токена выкинет пользователя | Обновление сериализовано и покрыто тестом на параллельные `401` |
| Медиа останется на edge-узле (архитектура А против контракта) | Вопрос задан автору backend; приложение исходит из контракта — медиа отдаёт сервер |
| Клип не с чем показать | Демо честно говорит «недоступно»; Media3 добавляется, когда появится запись |
| HTTP без TLS в локальной сети | Приемлемо для Stage 01, точечный network security config |
