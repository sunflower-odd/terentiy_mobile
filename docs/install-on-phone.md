# Установка на телефон

**Дата:** 6 октября 2026 года

Ставится **отладочная** сборка. Release не годится: в нём открытый HTTP
разрешён только для `10.0.2.2`, `127.0.0.1` и `localhost`, то есть для
эмулятора, а на телефоне сервер будет по LAN-адресу ноутбука. В debug открытый
трафик разрешён целиком — см. `app/src/debug/res/xml/network_security_config.xml`.

Отладочная сборка подписана отладочным ключом Android Studio. Для стенда этого
достаточно; в магазин такой файл не выложить, но на телефон ставится.

---

## Перед тем как отдавать кому-то

**Приложение работает только внутри той же сети, где стоит сервер.** Вне её оно
покажет «Устройство наблюдения не отвечает» и ничего больше — это не поломка, а
устройство Stage 01 (бэклог §8). Удалённому человеку отдавать APK пока
бессмысленно.

Вместе с файлом передать:

| Что | Пример |
|---|---|
| Адрес сервера | `http://192.168.0.42:8080` |
| Код установки | из `server/config/installation-codes.toml` |
| Условие | ноутбук с сервером включён и в той же Wi-Fi |

Что полезно сказать заранее:

- **нужен Android 8.0 или новее** (minSdk 26);
- **разрешений приложение не просит** — только доступ в интернет, он выдаётся
  при установке молча. Ни камеры, ни геолокации, ни доступа к файлам;
- **Android предупредит об установке из неизвестного источника**, а Play Protect
  может назвать приложение непроверенным. Для самостоятельно собранного APK это
  ожидаемо;
- **уведомлений не будет** — тревога видна, только пока приложение открыто.

Файл стоит переименовать во что-то узнаваемое: `app-debug.apk` → `terentiy-1.0.apk`.

## 1. Узнать адрес ноутбука в локальной сети

```bash
ipconfig getifaddr en0        # Wi-Fi
ipconfig getifaddr en1        # если Wi-Fi на другом интерфейсе
```

Получится что-то вроде `192.168.0.42`. Этот адрес понадобится в приложении.
Он меняется при переподключении к другой сети — если перестанет работать,
посмотрите заново.

## 2. Собрать APK

```bash
cd ~/AndroidStudioProjects/terentiy_mobile
./gradlew :app:assembleDebug
```

Файл: `app/build/outputs/apk/debug/app-debug.apk`, около 10–15 МБ.

Или в Android Studio: **Build → Build App Bundle(s) / APK(s) → Build APK(s)**,
затем во всплывающем уведомлении «locate».

## 3. Перенести на телефон

**По кабелю** — самое надёжное, ставит сразу:

```bash
~/Library/Android/sdk/platform-tools/adb devices        # телефон должен быть в списке
~/Library/Android/sdk/platform-tools/adb install -r app/build/outputs/apk/debug/app-debug.apk
```

На телефоне для этого нужна **отладка по USB**: Настройки → О телефоне → семь
раз нажать «Номер сборки» → вернуться → Для разработчиков → Отладка по USB.
При подключении телефон спросит разрешение — подтвердить.

**Без кабеля** — AirDrop, облако или мессенджер самому себе. Тогда на телефоне
открыть файл и разрешить установку из неизвестных источников, когда система
спросит. Android покажет предупреждение — для сборки, собранной самостоятельно,
это ожидаемо.

## 4. Проверить, что телефон видит сервер

Телефон и ноутбук — в одной сети Wi-Fi. Сервер слушает `0.0.0.0:8080`, так что
снаружи доступен.

В браузере телефона открыть:

```
http://АДРЕС_НОУТБУКА:8080/health
```

Должно вернуться `{"status":"ok","database":"ok"}`. Если страница не
открывается, дело не в приложении:

- телефон в гостевой сети или в мобильном интернете — переключить на ту же Wi-Fi;
- брандмауэр macOS блокирует входящие — Системные настройки → Сеть →
  Брандмауэр, разрешить входящие для Docker;
- сервер не запущен — `docker compose ps` в `terentiy_ai/server`.

## 5. Подключить приложение

На экране подключения:

| Поле | Значение |
|---|---|
| Адрес сервера | `http://АДРЕС_НОУТБУКА:8080` — не `10.0.2.2` |
| Код установки | из `server/config/installation-codes.toml` |
| Имя | любое |
| PIN | шесть цифр, и повтор |

Кнопка «Проверить адрес» обращается к `/health` и отличает «сервер не
отвечает» от «код не подошёл» — нажать её до подключения.

Дальше всё как в эмуляторе: главная со состоянием контура, история падений,
карточка события, запись.

## Обновить приложение на телефоне

```bash
./gradlew :app:assembleDebug
~/Library/Android/sdk/platform-tools/adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`-r` переустанавливает поверх, сохраняя данные: активация, PIN и отметки
просмотра остаются. Удалять с полной очисткой (`adb uninstall ru.terentiy.mobile`)
нужно только при смене формата хранилища.

## Если приложение на телефоне не подключается

1. **`/health` в браузере телефона открывается?** Нет — проблема в сети, см. шаг 4.
2. **Адрес введён с `http://` и портом?** `192.168.0.42:8080` без схемы не подойдёт.
3. **Логи приложения** — телефон по кабелю:
   `~/Library/Android/sdk/platform-tools/adb logcat | grep -i terentiy`.
4. **Ошибка про открытый трафик** (`CLEARTEXT communication not permitted`) —
   собрана release-сборка вместо debug.

## Как телефон связывается с сервером

По локальной сети, не по интернету:

```
телефон  →  Wi-Fi роутер  →  ноутбук:8080  →  Docker  →  API
```

Трафик не покидает роутер. Условия: телефон и ноутбук в одной сети, ноутбук не
спит, Docker поднят, брандмауэр пропускает входящие.

**Вне дома приложение не работает** — покажет «Устройство наблюдения не
отвечает». Это граница Stage 01, бэклог §8; там же пути, которыми это
снимается.

## Чего в этой сборке нет

- **Уведомлений о падении при закрытом приложении.** Push-канала в контракте
  нет, бэклог §13. Тревога видна только когда приложение открыто.
- **Шифрования трафика.** HTTP открытым текстом по локальной сети, бэклог §8.
  Для стенда приемлемо, для настоящей установки — нет.
