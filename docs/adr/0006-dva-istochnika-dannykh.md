# ADR-0006. Приложение работает от двух источников данных

**Дата:** 29 сентября 2026
**Статус:** принято, уточнено 1 октября 2026

**Уточнение 1 октября.** Решение в силе, но значение по умолчанию перевёрнуто:
теперь по умолчанию включён **сетевой** источник, а демо — явный выбор.
Переключатель продублирован на экране подключения, потому что до активации
Профиля не существует, а выбор нужен именно до неё. Прежний порядок оказался
ловушкой: свежеустановленное приложение «успешно» активировалось против
придуманных данных, и чтобы дойти до настоящего сервера, нужно было пройти
пять шагов — Профиль, выключить демо, выйти, «Забыли PIN?», активация заново.
Демо-источник сохраняется: он нужен для показа экранов и служит данными для
UI-тестов.

## Контекст

Контракт 1.1.0-draft описывает восемь новых маршрутов мобильного API. Ни один из
них backend не реализует: в `terentiy_ai/src/` нет ни одного упоминания, а
`POST /api/v1/auth/register` отвечает `404`. При этом сториборд и ТЗ пришли
вместе с контрактом, то есть приложение нужно показывать до готовности сервера.

Варианта «подождать» нет: если писать приложение только под живой backend, его
нельзя ни показать, ни проверить, ни обсудить с заказчиком.

## Решение

Репозитории объявлены интерфейсами (`AuthRepository`, `HomeRepository`,
`EventsRepository`), у каждого две реализации:

- `Network*` — по реализованному контракту 1.0.0;
- `Demo*` — сценарий внутри приложения с настоящим кадром с камеры установки.

Выбор делает `Switching*`-делегат, читающий режим из DataStore **при каждом
вызове**, а не один раз при создании: переключатель действует сразу.
По умолчанию — сетевой источник (см. уточнение выше).

Экраны о выборе не знают — они работают с интерфейсом.

## Следствия

- В день готовности backend переключение режима в Профиле проверяет сетевой путь
  без пересборки.
- Демо не изображает то, чего нет: клип в нём — короткое видео, собранное из
  настоящего кадра, а не запись падения; в тексте экрана это сказано прямо.
- Цена — вторая реализация каждого репозитория, около 300 строк. Она же служит
  источником данных для UI-тестов.
- Демо-код останется в сборке и после готовности backend: он полезен для показа
  и для проверки экранов без сервера. Удалять его специально незачем.

## Отвергнутые варианты

**Моки только в тестах.** Проверяли бы код, но не давали бы показать приложение.

**Отдельная сборка `demoDebug`.** Переключение требовало бы переустановки, а
пользы от изоляции нет: демо-источник не содержит ничего, что опасно оставить
в релизе.
