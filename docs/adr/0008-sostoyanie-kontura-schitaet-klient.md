# ADR-0008. Состояние наблюдения вычисляет клиент

**Дата:** 30 сентября 2026, пересмотрено 24 октября 2026
**Статус:** принято

## Контекст

Поля «состояние наблюдения» в контракте нет. С terentiy_ai 712afd2 (контракт
2.0.0-draft) `GET /api/v1/agents` отдаёт только `agent_id`, `name`, `camera_id`
и `online`; поля состояния камеры, потока и кадров убраны.

Пользователю нужно понять одно: работает наблюдение или нет и с какой стороны
проблема. Технических подробностей на экране быть не должно.

## Решение

Чистая функция `WatchStatus.of` в `domain/WatchState.kt`, пять состояний в
порядке серьёзности:

| Состояние | Условие |
|---|---|
| `NO_AGENT` | сервер ответил, агентов нет |
| `SERVER_UNAVAILABLE` | последний опрос агентов не прошёл: нет сети или ошибка 5xx |
| `AGENT_OFFLINE` | `online = false` |
| `CAMERA_UNAVAILABLE` | агент на связи, `current-frame` → `camera_unavailable` |
| `WATCHING` | агент на связи, `current-frame` отдал кадр |

Свежесть кадра проверяет репозиторий агентов: для каждого агента на связи он
запрашивает `current-frame` (метаданные кадра, без JPEG).

При нескольких агентах показывается худшее состояние.

## Следствия

- Матрица покрывается обычными unit-тестами, без Android и без сети.
- Остановку распознавания (worker) приложение не видит: кадры продолжают
  приходить. Для этого нужно время последнего обработанного кадра в мобильном API
  (замечание автору backend).
