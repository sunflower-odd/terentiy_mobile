# Переход на реализованный контракт 1.0.0

**Дата:** 30 сентября 2026
**Источник:** `terentiy_ai/contracts/openapi/mobile-server.openapi.yaml`, коммит `57f8e83`
**Предыдущий разбор:** [migration-to-contract-1.1.md](archive/migration-to-contract-1.1.md) — исторический

## Что случилось

30 сентября автор backend прислал пять коммитов: проект разделён на подпроекты
`server/`, `agent/`, `mobile-emulator/`, добавлен каталог `contracts/`, и **сервер
реализован** — PostgreSQL, миграции Alembic, Docker compose, отдельный ML-worker.

Реализован он по контракту `contracts/openapi/mobile-server.openapi.yaml` версии
**1.0.0**, а не по драфту 1.1.0, под который приложение было переписано днём
раньше. Драфт остался лежать в `docs/SDD-000/stage-01-person-detection/contracts/`
без изменений с 22 сентября. Автор не подтвердил, остаётся ли он в планах.

Проверено по коду, а не по документации: объявленные в `server/src` маршруты
совпадают с контрактом 1.0.0 поимённо, а в `src/terentiy/server` (старый монолит)
изменений с 6 сентября нет — этот каталог мёртв, root `README.md` говорит об этом
прямо.

## Что изменилось для приложения

| | Драфт 1.1.0 (приложение было написано под него) | Реализованный 1.0.0 |
|---|---|---|
| Вход | Логин и пароль от 12 символов | **PIN из шести цифр** |
| Сессия | access 15 минут + refresh с ротацией, logout, восстановление пароля | **бессрочный неотзываемый токен**, выхода нет |
| Главная | `GET /home` со состоянием наблюдения и интервалом опроса | `GET /agents` с nullable-флагами |
| Управление наблюдением | `PUT /agents/{id}/observation` | **нет вообще** |
| События | `possible_fall`, курсорная пагинация, `reviewed`, `statement` | подтверждённые падения, фильтр по агенту, без пагинации |
| Карточка | `GET /events/{id}` | отдельного маршрута нет |
| Клип | `preparing` / `available` | `clip_media_id` заполнен всегда |
| Медиа | `GET /media/{id}` | то же |
| Формат ошибок | `{code, message}` | **тот же** |

## Что сделано

**Удалено:** `TokenAuthenticator` с мьютексом и ротацией (ADR-0005 отменён),
`ObservationState`, `CameraState`, `HomeSummary`, `ClipStatus`, `EventPage`,
экраны логина и пароля, кнопка управления наблюдением, кнопка «Показать ещё».

**Восстановлено из коммита `f015d04`:** `Tri`, `Agent`, каркас `WatchState`,
экран PIN с блокировкой после неудачных попыток, коды ошибок. Контракт вернул
nullable-флаги, и удалённый днём раньше код снова оказался точным.

**Написано заново:** `WatchStatus` на семь состояний (ADR-0008),
`AuthorizedCall` — единственная точка реакции на `401`, `SessionHolder` —
наблюдаемая сессия, `SeenEventsStore` с водяным знаком (ADR-0009), `EventFeed` и
`AgentsFeed` — одна лента на два экрана с общим опросом и отступом при ошибках,
`MediaDownloader` с потоковой записью клипа и кешем, экран записи на `VideoView`,
блок разбора события.

**Ни одной новой зависимости не добавлено.**

## Что осталось нерешённым

1. **Какой контракт основной.** Пока автор не ответил, приложение следует
   реализованному. Граница DTO держит цену следующего перехода низкой: имена
   полей знает только `data/remote`, состояние контура — вычисляемая функция,
   «просмотрено» — за интерфейсом.
2. **Нет уведомлений.** Тревога видна только при открытом приложении. Это
   ограничение продукта, и закрывать его фоновым сервисом нельзя — см. бэклог.
3. **Вся история на каждый опрос**, вместе с ML-диагностикой каждого события.
   Просьба о `limit`/`since` — в бэклоге.
4. **Сироты в `mobile_devices`** при каждой переустановке приложения: маршрута
   удаления устройства нет.
5. **Токен бессрочный и неотзываемый** — клиент может стереть его только у себя.

## Что пропало из приложения и почему это не наша потеря

Управление наблюдением, пагинация, состояние «клип готовится», серверный признак
«просмотрено», текст события с сервера и восстановление пароля исчезли вместе с
маршрутами. Функциональность «новое событие» сохранена локальными отметками,
формулировка события теперь наша и живёт в `strings.xml`.
