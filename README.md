# Терентий — мобильное приложение (Android)

Клиент системы поведенческого мониторинга «Терентий» (SDD-000). Работает поверх
backend из репозитория [`terentiy_ai`](../terentiy_ai).

**Что умеет:** подключение устройства к установке по коду, вход по PIN, главный
экран с состоянием контура наблюдения, история подтверждённых падений, карточка
события с кадром с камеры, запись события с проигрывателем, профиль с выходом.

> **По умолчанию приложение работает с настоящим сервером.** Есть и показ без
> сервера — переключатель «Показ без сервера» на экране подключения: данные
> придумывает само приложение. Это приём для показа экранов и для диагностики,
> а не режим системы: режимы — демо и прод, и различаются они на стороне агента.

Установка на настоящий телефон — [`docs/install-on-phone.md`](docs/install-on-phone.md).

Пошаговые инструкции для всех трёх способов запуска — в
[`docs/how-to-run.md`](docs/how-to-run.md). Ниже — короткая версия.

## Быстрый старт

Нужны только Android Studio с JDK 25 и эмулятор с Android 8.0+.

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
adb uninstall ru.terentiy.mobile      # если стояла прошлая версия
./gradlew :app:installDebug
```

## Два режима системы

Различает их источник кадров у агента, и больше ничего:

- **демо-режим** — агент отдаёт серверу готовый видеофайл как поток. Сервер,
  распознавание, события, записи и приложение при этом настоящие. Так систему
  показывают и проверяют целиком, не падая перед камерой;
- **прод-режим** — агент берёт кадры с IP-камеры. Отличие от демо — две строки
  в конфигурации агента; сервер и приложение разницы не видят.

Сервер живёт в `terentiy_ai/server` и поднимается одной командой в Docker
(PostgreSQL, миграции, API и ML-worker). Агент запускается отдельно. Всё по
шагам — в [`docs/how-to-run.md`](docs/how-to-run.md).

На экране подключения: адрес `http://10.0.2.2:8080` для эмулятора либо
LAN-адрес ноутбука для телефона, код установки из
`server/config/installation-codes.toml`, имя, PIN из шести цифр. Кнопка
«Проверить адрес» обращается к `/health` и отличает «сервер не отвечает» от
«код установки не подошёл».

## Показ без сервера

Включить «Показ без сервера» на экране подключения — и встроенный сценарий за
минуту проходит всю матрицу состояний: «состояние неизвестно» → «наблюдение работает» →
событие падения с кадром и записью → кадры отстают → камера недоступна → агент
не отвечает. Код установки и PIN в этом режиме принимаются любые корректные.

## Что показывает главный экран

Состояние контура наблюдения приложение **вычисляет само** из технических полей
агента: управления наблюдением в контракте нет, отдельного поля состояния тоже.

| Что видно | Когда |
|---|---|
| Наблюдение работает | Агент на связи, камера подключена, кадры доходят до сервера |
| Состояние неизвестно | Агент ни разу не отчитался. Это не поломка, данных просто нет |
| Устройство наблюдения не отвечает | Сервер давно не получал heartbeat |
| Камера недоступна | Агент работает, картинки с камеры нет |
| Поток с камеры прервался | Камера подключена, видеопоток не идёт |
| Кадры не доходят до сервера | Агент снимает, но отправить не может — падение не будет замечено |

«Неизвестно» намеренно отличается от «недоступна»: агент, который ещё ни разу не
отчитался, — это не сломанная камера. Ниже видны время последнего кадра и время
последнего отчёта: без них экран выглядел бы живой картиной, хотя это срез.

**Событие падения** приходит с сервера как подтверждённое правилами по позе
человека. Заголовок утвердительный — «Падение», — но рядом всегда стоит
основание, а в свёрнутом блоке «Подробности» видно, какие правила сработали и с
каким голосованием. Решение принимала система, и пользователь должен это
понимать.

**Уведомлений нет.** Приложение сообщает о событиях только когда открыто:
push-канала в контракте не существует. Это главное ограничение, и в Профиле об
этом сказано прямо — см. [`docs/backlog-mobile.md`](docs/backlog-mobile.md) §13.

## Структура

```
app/src/main/java/ru/terentiy/mobile/
├── core/       — сеть (интерцепторы, реакция на 401), ошибки, опрос, время
├── data/
│   ├── remote/ — TerentiyApi, DTO контракта 1.0.0, мапперы, загрузка медиа
│   ├── local/  — сессия в AndroidKeyStore, настройки, отметки просмотра, кеш
│   └── repository/ — интерфейсы, network/, demo/, выбор источника, ленты
├── domain/     — Tri, Agent, WatchState, FallEvent, Session, MediaPayload
├── di/         — модули Hilt
└── ui/         — theme, common, navigation, activation, pin, home,
                  events, eventdetail, clip, profile
```

Экраны разделены на stateful-обёртку (`HomeScreen`) и stateless-содержимое
(`HomeContent`): содержимое проверяется Compose-тестами без графа зависимостей и
работает в превью Android Studio.

## Контракт

[`contracts/stage01-mobile-api.yaml`](contracts/stage01-mobile-api.yaml) —
**копия** версии 1.0.0, которую backend реализует. Оригинал принадлежит
`terentiy_ai`; в шапке файла указан коммит источника. Правки вносятся там и
переносятся сюда целиком.

Рядом в `contracts/archive/` лежит драфт 1.1.0 — спецификация вперёд, под которую
приложение было написано 29 сентября и которую backend не реализовал. Судьба
драфта не решена, поэтому он сохранён.

## Проверка

```bash
./gradlew :app:testDebugUnitTest          # логика, мапперы, ошибки, лента, контракт на MockWebServer
./gradlew :app:connectedDebugAndroidTest  # экраны, нужен эмулятор
./gradlew :app:lintDebug
```

Unit-тесты не требуют ни сервера, ни эмулятора. Именно они поймают расхождение,
если контракт изменится снова — а он менялся трижды за месяц.
